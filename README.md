# korean-ai-tell-detector

한글 글에서 "AI가 쓴 티"를 숫자로 계측합니다. 파이썬 1개 파일, 표준 라이브러리만 씁니다.

AI로 쓴 글이 티가 난다는 말은 흔합니다. 뭐가 티인지 물으면 대답이 보통 "느낌"입니다. 느낌은 고칠 수가 없습니다. 이 스크립트는 그 느낌을 건수와 밀도로 바꿉니다.

```bash
python3 detect.py 글.md "라벨"
```

## 출력

```
==============================================================
before (AI 티 의도 삽입)  (한글 227자 / 문장 11개)
  S1 18건   S2 0건   1만자당 793
  리듬 stdev 6.5  (E-1: 8 미만이면 S2)  최단 16 최장 38
    [S1] A-1  '~에 대해(서)'          <- "에 대해"
    [S1] D-5  의인화 추상 주어           <- "데이터가 말해"
    [S1] X-2  수사 질문 자답            <- "왜일까요? 바로"
    [S1] X-3  3연속 열거              <- "명확하고, 간결하고, 실행"
  E-2 동일 종결어미 최대 연속: 3회 (4회 미만 정상)
  말투: 해요체 0 / 합니다체 9 / -다체 2  -> 주 말투 합니다체, 혼용 2건
```

`samples/` 의 before와 after를 직접 돌려보면 차이가 보입니다.

| | S1 | 1만자당 | 리듬 stdev |
|---|---|---|---|
| `samples/before.md` | 18 | 793 | 6.5 |
| `samples/after.md` | 0 | 0 | 13.2 |

## 무엇을 보는가

다섯 축을 봅니다.

**1. 패턴 위반.** 번역투(`~에 대해`, `~를 통해`, `~에 있어서`, 이중 피동), 관용구(`결론적으로`, `본질적으로`, `시사하는 바가 크다`), 의인화 추상 주어, 결말 공식, 문두 접속사, 형식명사 결말, 헤징. 심각도는 S1과 S2로 나눕니다. S1은 한 번만 나와도 신호입니다.

**2. 문장 리듬.** 길이 표준편차가 8 미만이면 모든 문장이 같은 호흡이라는 뜻입니다.

**3. 종결어미 연속.** 룰북 E-2 는 `~다` 가 4문장 연속일 때를 위반으로 봅니다. 합니다체의 `습니다` 는 표준 어미라 구조적으로 반복되므로 위반으로 세지 않고 참고치로만 출력합니다. 룰북 문구가 `~다` 를 명시하기 때문입니다.

**4. 말투 혼용.** 해요체와 합니다체가 한 글에 섞인 건수를 셉니다. 섞는 것이 의도일 때도 있으니 판단은 사람이 합니다.

**5. AI 특유의 수사.** 대조 프레이밍(`A가 아니라 B`), 수사 질문 자답(`왜일까요? 바로`), 3연속 열거, 일반형 참여 유도, 가짜 구체성(`다들`, `대부분은`), 버즈워드, 줄표 남용.

직접 인용은 계측에서 제외합니다. 인용한 문장의 문체는 글쓴이 책임이 아닙니다. 큰따옴표, 백틱 코드 스팬, 코드 블록, 마크다운 인용블록이 해당됩니다.

이모지는 줄 머리의 구조 레이블 위치일 때 제외합니다. 사내 블로그 템플릿처럼 외부 규격이 이모지 레이블을 지정하는 경우가 있어서, 산문 속 장식만 계측합니다.

## 한계

정규식입니다. 문맥을 모릅니다.

- 한글 산문 전용입니다. 영문이 섞이면 줄표를 오탐합니다.
- 고유명사나 기술 용어가 패턴과 겹치면 오탐이 납니다. `재고,` 같은 명사를 연결어미로 보던 버그가 있었고 고쳤습니다. 비슷한 것이 더 있을 수 있습니다.
- 점수가 0이어도 좋은 글이라는 뜻은 아닙니다. 목적이 없는 글, 주장이 없는 글, 사실이 없는 글은 이 스크립트가 잡지 못합니다.
- 룰북보다 엄격한 규칙을 넣으면 멀쩡한 글을 깎습니다. 만들면서 네 번 겪었습니다. 이모지를 1개만 써도 잡던 규칙, 문두 접속사를 1회에 잡던 규칙, 리듬 임계를 8 대신 10으로 둔 것, 종결어미를 비율로 재던 것. 모두 룰북 문구로 되돌렸습니다. 규칙을 추가할 때는 룰북 원문과 대조하세요.

세 번째를 특히 봐주세요. 이 스크립트는 숫자의 진위를 모릅니다. 지어낸 숫자를 실측으로 바꿔도 점수는 움직이지 않습니다. 직접 격리해서 확인했습니다.

| 입력 (`samples/isolation/`) | S1 |
|---|---|
| `fake-number.md` 지어낸 숫자 + 중립 문장 | 0건 |
| `real-number.md` 실측 숫자 + 중립 문장 | 0건 |
| `hype-wrapper.md` 같은 지어낸 숫자 + 감싸는 말 | 3건 |

세 파일이 저장소에 있습니다. 직접 돌려서 확인하세요.

점수를 움직이는 쪽은 숫자를 감싸던 말입니다. 실측값이 없으면 그 빈자리를 hype 어휘와 가짜 구체성이 채우고, 이 스크립트가 세는 대상이 바로 그 어휘입니다. 그래서 점수가 0이어도 사실이 없는 글일 수 있습니다. 숫자의 출처는 사람이 확인해야 합니다.
